# ONOD Fonts — reliability and UX update, 11 October 2026

## Release status

Review branch: `feat/reliability-ux-2026-10-11`.
Baseline: `main@9274072227464e500a22ac6eea54b8c4bc8674c8`.
This is a substantial first implementation of the approved audit, not a declaration that all 75 backlog items are complete. Production is intentionally unchanged pending visual review and the remaining acceptance checks.

## Implemented

### Correct technical metadata

The Google Fonts importer now uses a nested TextFormat parser instead of regular expressions that ignored indented fields. All 1,190 existing evidence records were reparsed from their exact pinned Git blob SHAs. Family identity, license and catalog IDs were preserved. The write is atomic and aborts on any hash, identity, license or parse failure.

The repaired Google subset contains 328 variable families and 252 families with italic. None has an empty parsed weight or style list. These are counts for the pinned Google subset, not the entire catalog. Inter correctly exposes normal/italic, `wght 100–900` and `opsz 14–32`. Technical verification is now gated on a successful structured parse, independently of source/license identity.

Full before/after evidence: `evidence/google-metadata-repair-2026-10-11.json`. Parser regression fixtures retain the original Inter and Abel metadata text, not font binaries.

### Real font loading

The loader validates a non-empty set of matching loaded FontFace objects, including family, style and weight; it no longer treats `document.fonts.check()` as proof that a family exists. Requests are limited to four concurrent loading tasks. Catalog sources load near the viewport, while details and comparison request their selected faces directly. A measured desktop initial load requested five font sources rather than all twenty rendered cards.

0xProto, Geist Sans and Hubot Sans use pinned official upstream preview paths. Regular and selected bold faces were verified in browser tests. These paths do not upgrade unrelated licensing or glyph coverage claims. Failures remain visible and have a retry control. A separate notice warns when entered text uses a script not confirmed by the metadata; it does not claim a complete cmap inspection.

### Stable state and navigation

The Workbench's repeated URL writes have been removed. After two initial history replacements, an idle page produces zero further replacements in the measured test. URL role/ratio values, local selection, reorder and authoritative empty selection are consistent. Clearing the last font remains empty after refresh.

Catalog search ranks an exact family name before author/description substrings; Inter is the first result for Inter. Filters have removable chips and context-sensitive counts. Returning from a font restores all 80 loaded test records and the clicked card's viewport position and focus. Legacy preview links hydrate once; cleared text stays cleared. Custom text is no longer silently added to URLs as the user types. Sharing Workbench text is explicitly opt-in.

Storage reads/writes/removal are guarded. A denied-storage browser remains usable with a clearly indicated temporary in-memory session instead of a blank application. Saved imports merge validated known IDs and never erase the current collection on an invalid file.

### Responsive interface

The desktop sidebar and full navigation start at 1280 CSS pixels. Smaller widths use a real modal drawer/menu with focus isolation, Escape, scroll lock, unique IDs, focus restoration and resize cleanup. Desktop fixed sidebar position and sticky header/toolbar/footer geometry remain regression-tested.

The monochrome identity is retained. Controls, contrast, labels, focus styling and touch targets are more consistent. Size/sort controls remain available on mobile. Card actions support comparison and saving; detail navigation uses links with normal modifier-click behavior. The displayed specimen size is no longer silently capped in grid view.

The detail page puts the specimen before the long control panel on mobile; its measured top position is 346.5 CSS pixels at 390 × 844. Real style/axis controls, committed numeric inputs, reset and sample presets preserve the user's custom draft. Glyph samples include script groups and Unicode lookup, with an explicit limitation that this is not a full glyph map.

### Workbench and saved output

Workbench separates same-text comparison from a role-based pairing layout, with article/interface/hero previews, ordering, clear selected candidates and mobile controls. Preview typography uses real available normal/italic faces and disables synthetic styles.

Exports include CSS variables and complete role classes, Tailwind v4 theme configuration, explicitly labelled legacy Tailwind v3 configuration, and versioned JSON tokens. They retain selected scale, role sizes, weight/style, line height, tracking, fallback and source connection guidance. Google imports use the same verified design-space URL as the preview. Tailwind v4 compilation and legacy v3 CommonJS execution are exercised by tests.

Saved fonts have a single non-overlapping toolbar, search, recent/alphabetical ordering, pagination, comparison, local-only disclosure, ID-only JSON backup/import and guarded validation. No font binaries are embedded in backups or exports. Named project collections are not implemented in this release.

### Build, deployment and dependencies

Non-catalog routes and educational motion dependencies are lazy-loaded. The main JS entry measures 924.64 kB uncompressed / 191.76 kB gzip versus the audited 912.25 / 237.93 kB baseline: about 19% less gzip, but the richer repaired data makes the uncompressed entry slightly larger. The 150 kB gzip aspiration is not met and the existing large-chunk warning is not suppressed.

Build output materializes 1,353 known static route directories and a noindex 404. Static smoke tests verify known routes as HTTP 200 and an unknown path as HTTP 404 without relying on Vite's SPA fallback. These are route shells, not SSR or a completed SEO project. Production needs post-deployment verification after approval.

Vite is patched to 6.4.4. The final dependency audit before branch publication reports zero known vulnerabilities. This is not a security certification. CI now runs metadata/unit/build/static smoke and Playwright functional/layout/accessibility gates, and preserves browser evidence on failure.

## Verification

- Full `npm run check`: passed; includes 16 unit tests, evidence validation, TypeScript, production build, emitted-route and asset validation.
- Fixed/sticky layout regression: 2 scenarios passed.
- Chromium: final 30-scenario matrix covers functional paths, RU/EN catalog at 320/390/768/1024/1440/1920, and detail/Workbench/saved at mobile and desktop widths. The final machine-readable result is in `evidence/qa-chromium-2026-10-11.json`.

- WebKit: 12 functional scenarios passed. Evidence: `evidence/qa-webkit-2026-10-11.json`. Condition-based waits replaced fixed short delays in the shared browser tests; the assertions were preserved. Do not equate Playwright WebKit with a complete Safari/iPhone device certification.

## Deliberately outstanding

Production approval and post-deployment HTTP checks; named project collections; exhaustive per-glyph cmap/coverage and OpenType features; advanced independently editable role axes/weights and their portable configuration; a bounded long-session font cache/virtualized catalog; the tighter entry-payload budget; wider Protocol/About content/accessibility work; full external-source availability review across all 1,346 records; remaining 34 source/license trust-debt records; native Safari/iPhone/Android and screen-reader/manual 200% zoom acceptance.

The distinction between free use, open-source licensing, provider hosting and redistribution is preserved. No blanket license or download permission is inferred by this update.
